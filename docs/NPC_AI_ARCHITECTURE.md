# 溪谷镇 · NPC_AI_ARCHITECTURE

> 目标：让八个 NPC 在没有人推的情况下跑满七天，行为可读、可解释、可被玩家干预。
> 本文只写**代码里真的成立的东西**，每条都对应 `src/` 下的实现。

---

## 0. 分层

```
data.js       内容层：性格、职业、居民档案、建筑、装饰
world.js      空间层：地块、寻路、资源、作物、图纸
agent.js      个体层：需求、心情、记忆、动作结算
goals.js      决策层：目标打分 → 多步计划
language.js   语言层：事实 → 意图 → 句式，现场生成一句
learning.js   学习层：谈话策略、话题显著度、目标经验、情绪底色
llm.js        可选：外部模型改写台词（失败即退回本地）
dialogue.js   短句层：睡着/打招呼/双人回应的碎片
social.js     关系层：亲和/信任/熟悉度、闲话、秘密
sim.js        调度层：时间、换日、玩家、存档
render/ui     表现层
```

依赖方向单向向下：`goals → agent → world`，`social → agent`，没有任何反向依赖。
内容层不 import 逻辑层，所以加人可以只改 `data.js`。

时间单位：**1 刻 = 5 游戏分钟**，`TICK_MINUTES = 5`，`DAY_START = 360`（06:00）。
1× 速度 = 1.6 刻/秒，即 1 秒 ≈ 8 游戏分钟。

## 1. 个体状态机

每个 `NPC` 每一刻执行同一套流程（`agent.js` 的 `tickUpdate`）：

```
1. 需求漂移（睡眠时饥饿变慢、精力回升）
2. 若在移动：沿 path 前进 speed（默认 1.0 格/刻）
3. 若该行动作未完成：累计 progress，到 dur 就 finishAct
4. 若行动作完成：applyEffect 结算，进入下一步
5. 若没有计划：choosePlan() → 打分 → 取一个计划 → 设 stepIndex = 0
6. 若计划步骤全部完成：finishPlan（记录成就、清理状态）
7. 归一化需求到 0–100（normalizeNeeds，防止长期累积溢出）
```

顺序很重要：**先结算上一件事，再决定下一件事**。这保证 NPC 不会在"正在吃饭"
的同一刻又选中"去睡觉"，也保证计划失败时有机会重新决策。

### 1.1 需求漂移常量

| 需求 | 每刻变化 | 说明 |
| --- | --- | --- |
| hunger | −0.52（睡眠时 ×0.45） | 约 3.2 刻/点，一天不吃饭会掉到 20 以下 |
| energy | 醒着 −0.30；睡 +5.4 | 睡满 8 小时回满 |
| social | −0.40 × 性格系数 | 社交型衰减更快 |
| fun | −0.29 × 性格系数 | |
| purpose | −0.21 | 成就需求，最慢 |

### 1.2 心情

```js
mood = 40 + (hunger-50)*0.20 + (energy-50)*0.10 + (social-50)*0.16
          + (fun-50)*0.16 + (purpose-50)*0.10
          + mods.moodBase + Σ(memory.valence * memory.strength * 0.8)
          + clamp((beauty - 6) * 0.9, -8, 8)   // 街区美观度，基准 6
```

心情不是需求平均值的别名：记忆会持续加权，所以"被伤过的人"即使吃饱睡足也高兴
不起来。这是让经历留下痕迹的最小机制。

### 1.3 记忆

```js
addMemory({ text, valence, strength, kind, about })
```

- `strength` 每刻 ×0.9986（半衰期约 8 游戏小时/100 刻），所以昨天的争吵今天还剩一半强度。
- 保存时只留最近 30 条（`toJSON` 截断），避免存档膨胀。
- `about` 是相关 NPC 的 id 列表，闲话系统靠它找"可以传的第三者"。

## 2. 性格 → 系数

18 种性格（`data.js` 的 `TRAITS`），每个带一组 `mods`。`mergeTraits` 规则：

- **乘区键**（`hungerMul` / `energyMul` / `socialMul` / `funMul` 等）相乘；
- **加区键**（`moodBase` / `chatBonus` / `trustGain` / `conflictBias` / `gossipRate` 等）相加。

例：「勤劳 + 倔强」= 精力衰减更慢（乘）+ 冲突倾向更高（加）。

设计理由：乘区用来控制**节奏**（一个人活得多快），加区用来控制**倾向**
（一个人更容易往哪个方向走）。混用会让参数互相抵消，分开就好调。

## 3. 决策：目标打分 → 计划

`goals.js` 导出 6 个目标：`eat / sleep / work / social / relax / wander`。
每个目标有三个函数：

```js
score(npc, sim)  → 数字（当前有多想做）
thought(npc, sim)→ 一句玩家能看到的心里话
plan(npc, sim)   → 计划（步骤数组）或 null（此刻做不成）
```

`pickPlan` 的流程：

1. 对 6 个目标算 `score`；
2. 按分数降序，**依次尝试生成计划**，取第一个能生成非空计划的；
3. 计划是一串步骤：

```js
{ kind: 'goto', x, y, label }                  // 走到某格
{ kind: 'act',  id, dur, data, label }         // 做一个动作，dur 刻
```

例：农夫上工的计划不是"工作 4 小时"，而是
`去田里 → 浇水(2 刻) → 收割(3 刻) → 播种(2 刻) → 照料(3 刻)`。
每步都能失败（作物没了、地被占了），失败就 `failPlan` 并进入冷却，下一刻重新打分。

**这是本项目的核心可解释性来源**：档案页里显示的"此刻 → 步骤 1/2/3"就是这份计划
的原文，玩家看到的不是黑箱。

### 3.1 计划失败

`failPlan` 会：清空计划 → `failCool = 6`（6 刻内不再重复选同一目标）→ 写一条
心情轻微下滑的记忆。没有这一步，NPC 会在失败目标上空转，玩家会看到"卡住的人"。

## 4. 动作与结算

`applyEffect(act, step)` 是唯一修改世界和数值的地方（大 switch）。动作清单：

`eat / buyMeal / forage / work / harvest / water / plant / chop / build / chat /
relax / fish / paint / treat / serve / trade / watch / look / sleep`

每个分支只做三件事：改需求、动资源、写日志/记忆。**不做动画，不做叙事**——
叙事在上层（日志文本 + 想法气泡）。

例（`chop`）：

```js
const wood = w.chopTree(d.x, d.y);
if (wood) {
  sim.world.stock.wood += wood;   // 2–4
  this.coins += 2; n.purpose += 10;
  addMemory('砍倒一棵树…');
  log('老墨砍了一棵树（+3 木材）。');
}
```

节制规则写在 `goals.js` 侧：只有 `stock.wood < 32` 且当天砍伐 <3 棵时才把"砍树"
放进计划，否则回工坊做木工。**内容约束放在决策层，结算层保持笨拙**——这样加动作
不会破坏平衡。

## 5. 关系系统

每个 NPC 对每个 NPC 有一条关系记录：

```js
{ affinity, trust, familiarity, lastTalk }
```

- `affinity` 好感 0–100，决定标签：≥78 挚友 / ≥62 亲近 / ≥46 友好 / ≥32 点头之交 /
  ≥18 有点别扭 / 否则有芥蒂。
- `trust` 信任，决定"会不会说心事"。
- `familiarity` 熟悉度，决定"跟你说到多深"。

### 5.1 一次闲谈（`chatter`）

```js
compat = 0.28 + 共同性格*0.11 + (1-价值观差异)*0.33 + 聊天加成
delta  = 1.4 + compat*4.2 + (平均心情-50)/20 + 加成
吵架概率 = clamp(0.07 + 冲突倾向*0.045 - compat*0.06, 0.01, 0.26)
深谈：compat > 0.62 时 22% 概率（额外 +3.5 好感）
```

结算：双向好感变化（B 侧 ×0.92，表示"被动接受"略弱）、信任增长
`0.55 + compat*1.5`、熟悉度 +2、社交 +11/+10、乐趣 +4。
吵架时信任倒扣、双方写入负向记忆。

### 5.2 闲话（`gossip`）

```js
p = clamp(0.22 + gossipRate*0.6, 0.05, 0.85)   // 每次闲谈后判定
```

从说话人记忆里挑一条 `strength > 0.25` 且涉及第三者的，写成听话人的 **belief**：

```js
{ about: targetId, kind: 'secret'|'memory', text, source, tick }
```

信念和记忆分开存，因为玩家看到的语义不同：记忆是"我经历的"，信念是"我听说的"。
档案页里信念带来源，方便玩家判断可信度。

### 5.3 秘密

```js
if (rel.trust < 42) return;
if (!chance(0.14 + rel.trust/700)) return;   // 信任 42 → 20%，信任 90 → 27%
```

吐露后：听话人得到一条 `kind:'secret'` 的信念，双方各写一条高强度记忆，
日志出一条 `drama`，并写入 `sim.dramaticFlags`（用于统计"这局发生过几件大事"）。
每个秘密只对同一个人说一次（`secretToldTo` 去重），但可以被继续传出去。

### 5.4 台词生成（`language.js`）

台词不是池子，是"事实 → 意图 → 句式"三步现场生成出来的：

```js
gatherFacts(npc, sim)      // 8–12 条事实，全部从当前状态现算
chooseIntent(npc, sim)     // complain / share / ask / work / warm / observe
realWithRng(voice, ...)    // 这个人的句式 + 句尾 + 语气
compose(npc, sim, mode)    // 上面三步 + 去重，返回 { text, intent, fact }
```

- **事实从哪来**：天气、时辰、职业与库存（苗熟了没、木料够不够、酒馆还有没有食材）、
  未完工的图纸、自己的需求（饿了/困了/闷了）、与玩家的关系（生人/熟人/信得过）、
  最近三条记忆、听来的传闻。所以同一句话在第 3 天雨天和第一次见面时不可能一样。
- **意图怎么选**：心情低 → complain，心情高 → warm，社交需求低 → ask，正在干活 → work，
  手里有传闻 → share；再叠加性格 bias 与学到的 policy（见 5.5）。
- **句式**：每人一套 `VOICE`，六类意图各 2–3 个带 `{fact}{feel}{you}` 槽位的句子，
  外加自己的句尾。老墨短，阿梨绕，苏叶先问别人，铁牛把一切变成交易。
- **去重**：把所有 事实×句式×语气 的组合都算一遍，取与最近 16 条**最不相似**的那条
  （二元组 Jaccard）。同一事实连续出现加 0.4 惩罚；第二拍显式排除第一拍的事实。
  40 次连续交谈里约 70–75% 是不同句子，且没有连续重复——这条是自检断言的。
- **睡着的人**：`sleepLine` 轮换三句困倦的短句，不会永远回同一句。

### 5.5 学习（`learning.js`）

每个 NPC 有一个 `mind`，它真的会改后面的行为：

| 字段 | 学什么 | 怎么用 |
| --- | --- | --- |
| `policy` | 哪类谈话（抱怨/分享/提问/亲近）能换来好感 | `chooseIntent` 的权重项 |
| `topics` | 哪些话题对方有反应 | `gatherFacts` 的抽样权重 |
| `habits` / `habitBase` | 哪个目标比预期更解渴 | `pickPlan` 的 score 加项（±4） |
| `moodBase` | 这几天整体过得好不好 | 直接加进 `mood`（±7） |

- `rewardTalk`：用这次交流带来的好感变化当 reward，学习率 0.12，往"这次用的策略"上推。
  被奖励过的"多说心里话"，下一次更容易被选中。
- `noteHabit` 学的是**意外**而不是收益：先记每个目标的历史均值，只把超出预期的部分
  做 EMA。第一版直接学收益，结果"吃饭永远最划算"，木匠再也不去工地——被自检抓出来改掉的。
- `dailyMoodUpdate`：每天结算一次，日均需求低 → 情绪底色 −0.6，高 → +0.4，否则回中。
  连着几天过得差的人，之后开口就是低落的调子。
- 确定性：所有更新用 `sim.rng`、固定顺序；同种子两次 3 天长跑 policy 完全一致。
- 存档：`mind` 与最近 8 句 `_said` 一起进 `toJSON`，读档后策略延续。

### 5.6 可选的语言模型层（`llm.js`）

本地生成器负责"说什么"，外部模型只负责"怎么说"：

- 配置存在浏览器 localStorage（端点 / 模型 / Key），不经过任何服务器；清空即回纯本地。
- 提示词只喂：这个人的档案、当前状态、与玩家的关系、两条最近记忆、本地生成的那句原文；
  要求 34 字以内、不编造世界之外的人与事。
- 7 秒超时；非 200、空串、超 60 字、出现"作为 AI / 抱歉 / 无法"一律丢弃，保留本地那句。
- 所以断网、没 Key、模型胡说，游戏都照常跑——它是一层润色，不是依赖。

## 6. 玩家交互

| 接口 | 行为 |
| --- | --- |
| `maybeGreetPlayer()` | 每刻检查：距离 ≤2.3、好感 ≥26、冷却 220–360 刻、不在睡 → 主动出气泡 |
| `requestTalk(npc)` | 距离 ≤2.6 立刻 `talkNow`；否则 `approachTo` 走过去 |
| `talkNow(npc)` | 调 `playerTalk`：按对方当前目标给一句台词；熟悉度 ≥3 时可能说心事 |
| `requestGift(npc)` | 同上，靠近后扣 5 硬币，好感 +7，写记忆 |
| `placeBlueprint` | 校验地块与资源 → 扣材料 → 生成图纸 → 木匠计划里出现"建造" |

### 6.1 追人（approach）

NPC 会走动，所以"走过去说话"不能只算一次路径：

```js
approachTo → repathApproach(force)
  ├─ 距离 ≤2.6 → 触发交互
  ├─ 超过 deadline（请求时 tick + 70）→ 放弃并记一条"跟丢了"
  └─ 路径终点与目标当前位置偏差 >1.8 格 → 重新 A*
```

每刻最多重算一次，避免每帧 A* 打满 CPU。这是本版最容易被忽略但最影响手感的一段：
没有它，玩家点"交谈"后经常什么都看不到（NPC 走了）。

## 7. 世界与建造

- 地图 40×30，格 26px，逻辑分辨率 1040×780（4:3），实际按 DPR 缩放。
- 地形：草、路、水、土、地板、树桩、沙。A* 四向，阻挡 = 建筑 / 水面 / 不可走物件。
- 公共仓库：`{ wood, stone, food, seeds, coins }`。
- 装饰（`DECOR_DEFS`）：长椅 / 花圃 / 喷泉 / 路灯，各有材料成本与 `buildTicks`。
- 图纸流程：`world.placeBlueprint` 校验（草地、无物件、非街道、资源够）
  → 扣材料 → `blueprints` 入列 → 木匠计划插入 `build` 步 → 进度满 → `onDecorBuilt`
  → 装饰落到 `world.decor`，美观度 +1。

美观度 `world.beauty()` = 装饰数量加权（长椅 1 / 花圃 2 / 喷泉 5 / 路灯 1），显示在世界页签，
并作为心情公式的加法项 `clamp((beauty - 6) * 0.9, -8, 8)`：你改的街景会真的让居民舒服
一点或少一点。基准 6 是初始地图的装饰量，所以拆不改、加才涨。

## 8. 存档

`sim.toJSON()` → `{ version: 1, seed, tick, weather, stock, tiles(obj/crop/regrow),
blueprints, decor, npcs[], player, logs(最近 160), dramaticFlags }`。
`sim.restore(data)` **原地写回已有实例**（不重建 NPC），因为 UI 持有 sim 引用。
读档流程：`new Simulation(seed)` → `restore(data)` → 替换主循环里的引用。

代价：`restore` 必须手写每个字段的恢复，加新字段要记得两边都改。
好处：不需要序列化类实例、不需要迁移框架，原型阶段够用。

## 9. 性能

- 8 个 NPC、每刻一次决策，A* 只在需要时跑（目标移动/玩家追人）。
- 渲染每帧全量重绘 40×30 地块（1200 次 fillRect），在中端机上稳定 60fps。
- 颜色按 `terrain+variant` 缓存，避免每帧解析 CSS 颜色字符串。
- 长跑自检：7 天 = 2016 刻，纯逻辑在 Node 里 <1 秒。

瓶颈会出现在"NPC 数量 × 每刻打分"上。到 30 人以上时应该：
打分加冷却（每 3–5 刻算一次）、A* 结果缓存、地块渲染分块缓存。

## 11. 已知限制

1. **计划是固定序列**：没有"做到一半改主意"的机制（只有失败重选）。
2. **信念不参与决策**：听来的秘密不会改变 NPC 对第三者的好感，只显示在档案里。
3. **存档无迁移**：`version` 只是拒绝旧档，不做字段升级。
4. **句式仍然有限**：事实 8–12 条 × 每人每意图 2–3 个句式，连续聊 40 次约 70–75% 不重复；再往上需要更多事实源或接模型（5.6）。
5. **没有演出层**：人物只有位移与气泡，没有动作动画、没有表情、没有音效。
6. **主动搭话有节流**：同一个人 220–360 刻才会再开口一次，热闹程度是设计出来的而不是涌现的。
7. **学习只在会话内**：`mind` 随存档走，但没有任何跨局/跨版本的迁移或对照实验。
8. **玩家只能点，不能打字**：没有自由输入，所以"适应玩家的说话方式"目前只体现在话题显著度与策略权重上。


## 七、经济、政治与版图（第四轮）

### 7.1 镇公账

`sim.town` 是镇上唯一的账本：`coins`（公账余额）、`taxRate`、`buildFund`、`landOpen`、`council`、`mayor`、`orders`。

钱的三个入口：市集卖给镇上的货、税（每天按居民收入收）、旅人打零工创造的产出。三个出口：工资（底薪 + 技能×0.6）、委托、建设。

价格不是常数：

```
price = base × clamp(1.45 - stock/42, 0.62, 1.6) × clamp(0.9 + purse/900, 0.85, 1.25)
```

库存 26 的木料卖 5，库存掉到 2 就卖到 8 —— 于是"囤货"和"趁便宜买"都成立。

### 7.2 工作

居民：`JOBS` 里每份工作有工作时段与产出，农夫收成进仓、木匠把木材变成房子、酒馆消耗食材。工资按日结算，发不出来就欠薪（purpose −4、moodBase 下滑，并且会有一句抱怨进日志）。

旅人：镇务页「打零工（半天）」，条件三条 —— 8:00–18:00、饥饿 ≥18、24 刻冷却。工钱 11–15 枚从公账出，附近 6.5 格内的居民会记住「旅人今天在镇上帮了半天工」。

### 7.3 商业

市集四行货（木/石/食物/种子），买卖都过公账。库存低于 24 时系统会发委托：要 8–10 件，1.45 倍价 +10，三天内交货。委托是玩家早期最稳的现金流。

### 7.4 政治

四派立场：`welfare`（高税高福利）、`lowtax`（低税）、`build`（加税修公共设施）、`order`（秩序优先）。每人的立场由职业与性格推出来（医生偏 welfare、商人偏 lowtax、守卫偏 order）。

每 7 天选举一次：`score = 声望 + rng(−4,4) + 得票×12 + 连任加成`，前 3 名进议会，第 1 名当镇长，并且当场改写税率、建设比例、是否开放购地。

玩家也能参选：声望 ≥40 才有资格，参选会写进每个居民的`politcs` 记忆；当选后提案成功率大幅提高。

### 7.5 版图

四块 3×3 荒地，购地价 `120 + 45 × 已占地数`，需要镇长是「开放外地土地」派或提案通过。买下后放一张「新居」图纸（木 10 石 3），木匠盖完，第二天有移民搬进来 —— 新 NPC 有独立档案、职业、性格与关系，从第 9 个人开始，镇子会自己长。

### 7.6 记忆怎么参与

每条记忆带 `kind`（work/food/social/politics/…）与 `topic`（九类）。玩家说的话会被解析成 topic，写进记忆；下次聊到同一话题，生成器优先挑同 topic 的事实，这就是"他记得你上次问过什么"。

居民之间也会传：传闻带 topic 扩散，听的人 `learnFromOthers` 给自己的话题加权，于是谣言会改变一个人爱聊什么。


## 八、社会系统（第五轮）

这一层让「智能」落进日子里：一个人不是只有心情和目标，他有身体、有学历、有家、有可能会犯法，也会被玩家指挥。

### 8.1 指令（src/orders.js）

| 指令 | 目标点 | 动作 |
| --- | --- | --- |
| 去上工 | 自己的工位 | work |
| 回家休息 | 自己家门口 | sleep |
| 去学堂 | 学堂 | study |
| 去市集 | 酒馆吧台 | buyMeal |
| 去巡查 | 主街两点 | look → look |
| 找某人聊聊 | 目标 NPC | chat |

约束：必须距玩家 4.5 格内，或玩家是镇长；睡着的人叫不动；指令 160 刻过期。
执行：`npc.order` 在 `tickUpdate` 里优先于自选计划，`orderPlan()` 翻译成两步计划，执行时写一条 `order` 类个人史。

### 8.2 身体与学堂

- 健康 0–100：每天基础磨损 0.35；饿 +0.8、累 +0.5、雨天 +0.2；吃饱睡好每天回 0.5；<38 生病，>62 痊愈。
- 生病会自己去找苏叶（每 20 刻扫一次），`treat` 回健康。
- 学识 0–100：学堂听课 +1.6，全技能 +0.05；学识越高，`study` 目标吸引力越低（毕业感）。

### 8.3 恋爱、家庭、出生

- 成家条件：异性、单身、≥18 岁、双方好感 ≥62/58、每天 5% + 8%×好感。
- 成家后每天 3% 生子（每对最多 2 个），孩子是真正的新 NPC（6 岁、学识 8、双向好感 88），会自己长大、上学、进关系网。
- 孩子进存档：`toJSON` 存全量档案，`restore` 先补建缺失的人再写状态。

### 8.4 治安

两种动因：饿（hunger<30）会直接动手拿粮；钱少又心里不平衡（coins<12 且 mood<50）会找机会摸别人口袋（粮仓空了就偷最有钱的那个）。
石头在 12 格内且醒着时 55% 抓住：罚 min(coins,12) 进公账、关 120 刻、好感 −14、写 drama 日志。

### 8.5 个人史

`npc.note(text, kind)` 记 `{t, kind, text}`，上限 60 条；同一句两小时内重复只刷新时间。
类型：act（上工/听课/看病…）、say（说了什么）、order（被指挥）、crime、family、event、market。
UI 在「个人史」区块倒序展示最近 18 条，带游戏内时间。


## 九、神迹、系统等级与互相影响（第六轮）

### 9.1 神迹（src/god.js）

玩家不是镇长，是镇子上空的一只手。信仰值每天结算：`1.6 + 平均心情/100×2.2 + 美观×0.18 + 系统等级加成`。

| 神迹 | 花费 | 效果 |
| --- | --- | --- |
| 祝福 | 8 | 好感 +10、信任 +4、乐趣 +12、情绪底色 +2 |
| 惩戒 | 10 | 好感 −12、信任 −6、成就感 −10、乐趣 −10、情绪底色 −3 |
| 点醒 | 6 | 成就感 +20、学识 +2 |
| 重塑 | 24 | 随机多一种天性，重算性格乘区（从此所有行为受影响） |
| 治愈 | 12 | 健康回到 92、病痛清除 |

每次神迹都写进个人史（kind=god）、写一条记忆、记一条 drama 日志。信仰等级随累计花费升到 5 级。

### 9.2 系统等级（src/development.js）

六个系统各有自己的分数与五级台阶（0 / 55 / 130 / 240 / 400）：

| 系统 | 分怎么来 | 升级给什么 |
| --- | --- | --- |
| 市集 | 公账 + 成交 + 库存 | 物价 +3%/级、委托上限 +1 |
| 学堂 | 平均学识 + 听课次数 | 学识增速 +12%/级 |
| 治安 | 抓贼 ×16 − 案件 ×6 | 巡查成功 +6%/级、失窃 −5%/级 |
| 农事 | 收获 ×5 + 粮食 + 耕地 | 生长 +8%/级、收成 +6%/级 |
| 镇政 | 提案 ×18 + 议会席位 | 提案通过 +4%/级、公账 +4%/级 |
| 家宅 | 成家 ×22 + 生子 ×26 + 伴侣 | 好感更快、新生儿更健康 |

升级当天记日志「X 升到 N 级——效果」，写里程碑，并 +6 信仰。镇务页显示「镇子的底子 12/30」。

### 9.3 互相影响（src/influence.js）

每天结算一次，四件事：

1. **传艺**：学识 ≥55 的人带一个比自己低 12 分以上的人 → 对方学识 +0.6、随机技能 +0.12、好感 +2.4，记一条 learn 记忆。
2. **结怨**：同行、双方心情都低、好感在 24–62 之间 → 10% 概率闹别扭，双方好感 −7。
3. **探病**：有人生病且好友好感 ≥52 → 45% 概率去探望，病人健康 +3、好感 +3。
4. **情绪传染**：每个人的情绪底色以 0.18 系数向全镇平均靠拢。

### 9.4 称号（titleOf）

在押 / 病中 / 惯偷（≥3 次）/ 状元（学识 ≥88）/ 读书人（≥68）/ 一族之长（≥2 个孩子）/ 有家室的人 / 富户（≥260 硬币）/ 一把好手（技能均值 ≥7）/ 孩子。显示在个人页「身份」里。
